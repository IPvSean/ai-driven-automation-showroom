= Section 1 Part 2 - Smart Alerts and Dual-Path Remediation

== Objective

In this section, we will configure **Smart Alerts** that integrate directly with **Ansible Automation Platform** through Instana's Action Catalog. You'll learn how Instana uses NLP (Natural Language Processing) to intelligently recommend AAP job templates based on the incident context. Then we'll trigger a service failure and execute remediation through two different paths: direct automated response (EDA) or manual selection from Instana's intelligent recommendations (Action Catalog UI).

By the end of this module, you'll understand the complete architecture for **intelligent AIOps**: observability detects the problem, AI recommends solutions, and you choose between automated or human-guided remediation.

== Learning Objectives

After completing this module, you will be able to:

* Create Smart Alerts integrated with Ansible Automation Platform
* Understand how Instana's NLP features surface intelligent job template recommendations
* Use the Instana Action Catalog to manually select remediation actions
* Execute remediation through the Instana UI (manual path)
* Execute remediation through Event-Driven Ansible (automated path)
* Understand the trade-offs between automated and intelligent remediation

== Architecture: Two Paths to Remediation

Instana provides two complementary paths for incident response:

=== Path 1: Automated Direct Remediation (Immediate, Rule-Based)

[source, text]
----
Instana Smart Alert (OPEN)
           ↓
Webhook POST to EDA
           ↓
EDA Rulebook (instana.yml)
  condition: event.payload.issue.state == "OPEN"
           ↓
run_job_template: "LINUX | Web App | Restore"
           ↓
AAP executes immediately (no approval needed)
           ↓
✅ Service restored in seconds
----

**Advantages**:
* Fastest response time
* Zero human intervention
* Predictable, deterministic
* Good for known failure modes

**When to use**: Service restart, connection reset, memory cache clear—simple, safe operations

=== Path 2: Intelligent Manual Selection via Action Catalog NLP (Informed Decision)

[source, text]
----
Instana Smart Alert (OPEN)
           ↓
Action Catalog syncs with AAP
  (NLP scores job templates by relevance)
           ↓
Students see ranked recommendations in Instana UI:
  1. "Restore Web App Service" (High confidence)
  2. "Check Service Health" (Medium confidence)
  3. "Collect Diagnostics" (Low confidence)
           ↓
Student clicks "Approve & Execute"
           ↓
Instana calls AAP API
           ↓
✅ Service restored (with auditing)
----

**Advantages**:
* Informed decision-making
* Visibility into multiple remediation options
* AI-recommended actions ranked by relevance
* Full audit trail

**When to use**: Complex incidents, critical systems, learning/training, governance requirements

== Prerequisites

Ensure the following are already set up:

1. **Instana agent running** on `node2` with the Flask application

== Step 1: Verify AAP Templates Are Available for Instana Sync

Before creating Smart Alerts, let's verify that your AAP job templates are visible to Instana for NLP matching.

=== Check AAP Organization and Templates

1. Log into Ansible Automation Platform
2. Navigate to **Administration** → **Organizations**
3. Verify the organization `Instana AIOps` exists
4. Click on it and verify it contains these templates:

   * `✅ LINUX | Web App | Restore` (primary remediation)
   * `✅ LINUX | Web App | Break` (for testing)
   * (Optional) `Check Service Health`, `Collect Diagnostics`, etc.

image::aap_instana_org_templates.png[AAP Instana Organization Templates, link="_images/aap_instana_org_templates.png", window=blank]

[NOTE]
====
The Instana backend periodically polls your AAP instance to discover templates. This polling happens automatically and requires no manual triggering. The `instana-sensor` user with Execute role on the `Instana AIOps` organization is the identity used for this discovery.
====

=== Verify Template Descriptions for NLP Matching

NLP (Natural Language Processing) works by comparing:
* Alert text: "Number of calls is anomalously low"
* Template names and descriptions

1. Click on `LINUX | Web App | Restore` template
2. Check the **Description** field contains keywords like:
   * "restore" or "recovery"
   * "service" or "web app"
   * "calls" or "throughput"
   * "down" or "outage"

Example description:
```
Restore Web App Service - Fix anomalously low calls and service outage.
Starts the lab-webapp service and verifies it is responding to health checks.
Use this when Instana detects service latency spikes or call rate drops.
```

These keywords ensure NLP gives this template a **High confidence match** (typically 0.8+) when the "calls anomalously low" alert fires.

image::aap_template_description.png[Template Description for NLP, link="_images/aap_template_description.png", window=blank]

[NOTE]
====
If your templates don't have descriptions, add them now. Instana syncs description changes automatically (check back after ~5 minutes). Better descriptions = better NLP matches = smarter recommendations.
====

== Step 3: Create a Smart Alert for Service Monitoring

A **Smart Alert** continuously monitors your service and fires when anomalies are detected. Unlike traditional threshold-based alerts, Smart Alerts use baseline learning.

=== In the Instana UI:

1. Navigate to **Services** (left navigation)
2. Search for and click on your service: `lab-webapp-{{ guid }}`

image::instana_services_search.png[Services Search, link="_images/instana_services_search.png", window=blank]

[start=3]
3. In the service view, click the **Add Alert** button (top right)

image::instana_add_alert_button.png[Add Smart Alert, link="_images/instana_add_alert_button.png", window=blank]

[start=4]
4. Configure the alert with these values:

[options="header"]
|===
| Field
| Value

| Alert Name
| `{{ guid }} Web App - Calls Drop Detection`

| Scope
| Specific service: `lab-webapp-{{ guid }}`

| Metric
| Calls (throughput)

| Condition
| < 1 (less than 1 call per minute)

| Evaluation Granularity
| 1 minute

| Alert Channel
| `EDA Automated Remediation - {{ guid }}`
|===

image::instana_smart_alert_config.png[Smart Alert Configuration, link="_images/instana_smart_alert_config.png", window=blank]

[start=5]
5. Click **Create Alert**

The alert is now active and monitoring. When `lab-webapp-{{ guid }}` stops responding (calls drop below 1), Instana will:
* Fire the alert (state = OPEN)
* Send a webhook to your EDA listener (Path 1: automated)
* Display recommendations in the Action Catalog (Path 2: manual)

[NOTE]
====
Smart Alerts are **threshold-less** by default, using ML to learn normal behavior. We've explicitly set `< 1` for clarity in this lab. In production, you'd often leave the condition blank and let Instana's ML determine the threshold.
====

=== Understanding NLP Confidence Scoring

The Action Catalog displays **confidence scores** for how well each template matches a given incident:

[cols="1,3,2", options="header"]
|===
| Confidence
| Meaning
| Example

| **High (0.8+)**
| Strong semantic match to incident text
| "Restore Web App Service" matching "calls drop" alert

| **Medium (0.5-0.8)**
| Partial match, likely relevant
| "Check Service Health" for calls drop

| **Low (< 0.5)**
| Weak match, probably not relevant
| "Collect Diagnostics" for calls drop
|===

The NLP works by analyzing:
* Alert text: "Number of calls is anomalously low"
* Template name: "Restore Web App Service"
* Template description: (contains keywords about recovery, service, calls)

**Result**: High confidence match → shown first in recommendations

[NOTE]
====
NLP is built into Instana. No external LLM calls needed. Instana uses word embedding and semantic similarity to score templates. This makes it fast, offline-capable, and compliant with data residency requirements.

Wait 1-2 minutes for the alert to evaluate and fire:

1. You'll see an **alert notification** appear in Instana
2. The alert state is **OPEN** (problem detected)

== Understanding the Dual-Path Architecture

=== When to Use Path 1 (Automated EDA)

✅ **Use Path 1 when**:
* Failure mode is well-known and safe (service restart)
* Need fastest possible response (milliseconds matter)
* No compliance requirement for approval
* Intent is full automation with zero human touch

❌ **Don't use Path 1 when**:
* Remediation could have side effects
* Regulatory/governance requires human review
* Multiple remediation options exist (need selection)
* Incident context should inform the decision

=== When to Use Path 2 (Manual Selection)

✅ **Use Path 2 when**:
* Multiple remediation options available
* Need human decision-making
* Compliance requires audit trail
* Learning/training scenario (understanding options)
* Incident context is complex

❌ **Don't use Path 2 when**:
* Need immediate response (seconds matter)
* Failure mode is deterministic (only one right action)
* Manual step would be bottleneck

=== The Instana + AAP Architecture

```
Instana detects incident
         ↓
    ┌────┴────┐
    ↓         ↓
  Path 1    Path 2
  (EDA)    (Manual)
    ↓         ↓
  Auto       Human
 Trigger    Clicks
    ↓         ↓
  AAP API  AAP API
    ↓         ↓
Restore    Restore
```

Both paths call the same AAP job templates. The difference is **trigger mechanism**: webhook (automated) vs. HTTP API call from Instana (manual).

Instana provides **AAP integration credentials** (org + user) that allow it to discover and call job templates. This integration is bidirectional:
* **Instana → AAP**: Discover templates (polling) & execute (API calls)
* **AAP → Instana**: (Optional) Send events/status via webhook
